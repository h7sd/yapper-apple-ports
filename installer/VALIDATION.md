# Installer validation snapshot

On 2026-10-30 the native installer was built using Apple Swift 6.4.2/Xcode on Apple Silicon, targeting macOS 13. The release executable contains arm64 and x86_64 slices and links only Apple system frameworks and Swift runtime libraries. It does not require Node.js at installation time.

The Swift Testing suite contains **27 test functions in five suites, with parameterized cases**. It exercises signed temporary app fixtures without launching them, canonical and legacy markers, bundled-source selection, source/signature tampering, rejection of a re-signed app with the wrong reviewed runtime checksum, explicit replacement and restoration, preservation of settings, running-app rejection, symlink path rejection, bounded ASAR reads, changed-destination refusal, rollback after a denied config write, and interrupted-restore journal recovery. Additional cases cover equal-ASAR recovery, missing backups, legacy receipts, and settings changed during staging. All passed. Fixture copies and profiles are created in temporary directories; no real Yapper app or user profile is modified by these tests.

The reported preview error was reproduced read-only: a selected older app failed strict signature verification because of Finder metadata/resource forks and contained no plugin-runtime marker. The replacement Setup includes and selects a compatible client, provides Use bundled client to reset its source, and reports actionable validation errors. A signed nested Renderer helper fixture verifies that an older metadata-affected destination can be upgraded and restored while its original attributes, quarantine, signatures, profile data, and plugin preferences remain unchanged. Only a temporary copy has the two signature-blocking attributes removed, and that copy must pass full strict signature verification with matching ASAR bytes. Metadata plus content tampering is rejected; new sources keep strict original verification.

The standalone universal installer ZIP is checked after extraction with `codesign --verify --deep --strict`, `lipo`, and its CLI `--version`. Self-contained setup variants additionally use the same native validator to inspect their bundled client, checking its Yapinplugger version marker, reviewed bundle hash, relative bundle links, nested signatures, and client architecture. Independent bounded ASAR reads verify that the packed Yapinplugger and appearance scripts match both reviewed release hashes and the current source bytes. `scripts/verify-installer.mjs` reproduces those artifact checks and emits a report containing archive names and hashes rather than local source paths. All artifacts include the independently authored installer's MIT license and provenance boundary.

The renamed Apple Silicon Setup opened with the window and menu title **Yapinplugger**. Native accessibility confirmed that its source defaults to its own `Contents/Resources/Yapper.app`. Clearing only that new window's source field disabled installation; clicking **Use bundled client** restored the included app path and ready status. The GUI source remains unchanged after a final recovery-only core correction; rebuilt archives are verified separately. No Install, Enable, Disable, or Restore action was invoked, and the user's older installer window and choices were preserved. Source-chooser cancellation and the end-to-end GUI installation remain untested. No screenshots containing local profile paths are published.

The Intel slice has not been run on Intel hardware, and the minimum macOS 13 deployment has not been tested on a macOS 13 machine. Native app signatures are ad-hoc; there is no Developer ID identity, notarization, privileged helper, or malware certification. Backup and rollback checks cover selected failure cases rather than every possible process crash, disk failure, or adversarial concurrent filesystem change.
