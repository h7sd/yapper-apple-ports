# Server organization and notifications

`Core/NativeServerOrganization.swift` and `UI/NativeServerOrganizationViews.swift` add native folder/order editing and notification settings. `NativeServerViews` integrates grouped server navigation, **Sortieren**, server/channel/category notification entries and the existing server-report composer. Fixtures remain read-only. Folder writes are disabled until the current organization has loaded successfully, and invalid layouts cannot omit, duplicate or introduce a server.

Source evidence belongs to the immutable public web closure recorded in `native-parity.json` (`ev_6142d5da0be52935da21de4955bc1734f71172f47d8f84286fbe6fc27471aaec`). Offsets below are zero-based UTF-8 bytes; hashes are retained in that machine-readable manifest:

- `2lxxd-jx-9d4l.js` at 84444 reads `user_server_folders.folders` for the current `user_id`; at 85339 writes `{user_id,folders}` via upsert, flattens rail order and restores the previous folders if saving profile order fails. Folders contain `{id,name,color,servers}`, at most 50 folders, 100 servers each and 32 Unicode code points in names. Folders with fewer than two joined servers become ordinary rail entries. Native editing supports creation, membership selection, internal/top-level reordering, custom names/colors and dissolution. `server_folders` and `folder_custom` gates are preserved.
- `33-dglfmrlo2q.js` at 127899 writes `profiles.server_order` filtered by the current `id`. Native requests returned own-profile identity to avoid reporting RLS-filtered zero-row updates as success. This is a two-write operation with best-effort compensating folder rollback, not an atomic backend transaction.
- `03nx2jt6m1jmz.js` at 4361 uses `set_notify_level{sid,cid,lvl}`, at 6083 `set_server_mute{sid,mins}`, at 6569 `set_category_level{cat,lvl}` and at 7003 `set_category_mute{cat,mins}`. Channels use `set_notify_mute{cid,mins}`. Durations are 15/60/480/1440 minutes, null indefinitely and zero to unmute. `my_notify_settings`, `server_mutes` and `unread_counts_v2` supply current state, expiry and lifted mutes. Native controls preserve server-scoped `channel_notify` and `quick_notify` gates.
- `3g3h29e2_tjc9.js` at 96347 confirms the notification level literal is `none`, alongside `all` and `mentions`. Channel/category null levels restore the server default; server defaults cannot themselves be null. Category changes affect existing non-thread channels; new channels inherit the server default.
- The observed ticket helper in `33-dglfmrlo2q.js` calls `close_ticket{cid}`. Its native context-menu entry requires `ticket_by` and is exposed to the ticket author or server owner. The official UI also allows users with resolved channel `manage_messages`; the native compact entry deliberately leaves that additional role/override case incomplete. Service authorization remains authoritative. An ordinary text channel cannot invoke the ticket service.

`NativeServerOrganizationTests.swift` contains 11 synthetic wire/model tests for current-user filters, ordering, folder limits/membership, write order/rollback, exact level/mute targets, expiry/lifted state, invalid input and ticket closure. The existing DM preference regression also checks both actual bootstrap flag arrays and keyed flag maps. Isolated Swift 6 typechecking uses presentation stubs only for unrelated call/conversation/report views; it is not a full app test.

No actual organization, notification, report or ticket state was changed. Native push delivery, cross-device preference event propagation and physical-device behavior remain unverified. Invite revocation remains a gap: the bounded inspected closure established invite creation/lookup and vanity changes, but no exact revocation consumer was found; no guessed DELETE/RPC was introduced.
