# Native conversation preferences

The native DM/group-chat list now exposes **Chat-Einstellungen** from each row's context menu. It supports account-scoped pin/unpin (50-chat limit), hiding without leaving a group, and notification mute/unmute. When the service enables `quick_notify`, the native sheet offers the official 15-minute, 1-hour, 8-hour, 24-hour and indefinite mute choices. The ordinary DM notification menu in the official client deliberately excludes the server/channel all-message/mentions-level selector; native DMs therefore do not invent one.

The implementation is `Core/NativeConversationPreferences.swift` and `UI/NativeConversationPreferencesView.swift`. `NativeConversationList` sorts pinned conversations first and filters hidden conversations. A realtime message newer than `hidden_at` reveals a chat using `Conversation.lastMessageAt`. Opening a DM from a profile clears the current user's `channel_members.hidden_at`, matching the official reopen path. Hiding and restoring require a returned membership row so an RLS-filtered zero-row update cannot display success. Writes only update native state after the service accepts the operation; pin writes first read the current ordered server value rather than overwriting a stale cached list.

Validation uses synthetic transport responses in `NativeConversationPreferenceTests.swift` for route/method/body/account filters, hidden-chat revival, lifted mutes, feature gates, fresh pin reads and limits, legacy/timed mute, malformed IDs and zero-row writes. `SocialFeatureTests` also verifies the reopen request. No real account preferences were changed. The DEBUG UI fixture skips these service reads and rejects preference writes. OS push registration/delivery, call alerts and cross-device realtime preference synchronization are separate integrations and are not established by these wire tests.
